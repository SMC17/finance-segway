# Parallel-Agent Collaboration Protocol

This repository is intentionally developed by multiple coding agents and human reviewers. The goal is not to merge every output. The goal is to preserve the strongest implementation of each component while keeping the history auditable and the work reproducible.

## Canonical branches

- `main` is the current reviewed baseline.
- Claude sessions work on `claude/<task>` branches.
- Codex / ChatGPT sessions work on `agent/<task>` branches.
- Cross-agent synthesis happens on a fresh `agent/integrate-<task>` branch created from the latest `main` after parallel work lands.

No agent should force-push another agent's branch or write directly to `main`.

## Integration sequence

1. **Snapshot the baseline.** Record the current `main` SHA before starting.
2. **Isolate parallel work.** Each agent owns its branch and commits small, named units of work.
3. **Compare by component.** Review file-level and model-level differences; do not select a whole branch merely because it is newer.
4. **Create a fresh integration branch.** Start from the latest merged `main`, not from either stale feature branch.
5. **Port only net improvements.** Preserve useful mechanics from both implementations and eliminate duplicated or weaker paths.
6. **Regenerate artifacts.** A changed builder must regenerate its workbook; binary templates and source builders must remain in parity.
7. **Run acceptance gates.** Do not merge until all relevant gates below pass.
8. **Open a draft PR.** The PR body must state what came from each branch, what was rejected, and why.

## Model acceptance gates

Every workbook change must pass all applicable gates:

### Structural

- Required tabs exist for the archetype.
- Inputs, calculations, outputs, checks, sources, and refresh history are separated.
- The Cover sheet keeps `Last refreshed` in `C6` and the next material date in `C7`, which the weekly refresh scanner reads.
- Scenario selection is explicit and does not require overwriting formulas.

### Formula integrity

- No `#REF!`, `#DIV/0!`, `#VALUE!`, `#NAME?`, `#N/A`, or circular-reference errors.
- Totals sum the relevant ranges directly.
- No hidden magic numbers inside formulas when the value belongs in assumptions.
- Debt, cash, recovery, and coverage identities reconcile.

### Modeling conventions

- Blue text and yellow fill: editable hardcodes.
- Black text: same-sheet formulas.
- Green text: cross-sheet formulas.
- Zeros display as `-`; negatives display in red parentheses.
- Units are stated in headers.
- Key outputs and status checks are visible without hunting through the workbook.

### Source and maintenance discipline

- Raw assumptions have an identified source or a clearly marked placeholder.
- A Sources tab records URLs, as-of dates, and methodology notes.
- RefreshLog exists and is append-only for material updates.
- Weekly-refresh structural checks know the workbook's required tabs.

### Reproducibility

- The committed `.xlsx` is generated by the committed builder.
- Re-running the builder yields the same workbook structure and formulas.
- Visual rendering is reviewed for clipped labels, unreadable widths, broken formats, and misplaced controls.

## Component-selection rubric

When two agents implement the same feature, compare them on:

1. Correctness and absence of circularity.
2. Depth of domain mechanics.
3. Auditability and visible checks.
4. Scenario and sensitivity design.
5. Source discipline.
6. Reproducibility and test coverage.
7. Simplicity relative to the economic problem.

The integrated version may combine parts of both. A larger implementation is not automatically better.
