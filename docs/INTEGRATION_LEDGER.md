# Finance Model Library Integration Ledger

This ledger tracks the synthesis of the active Claude Code and ChatGPT/Codex lanes. It is intentionally component-specific: a branch can contain the best implementation of one model and a weaker implementation of another.

## Comparison point

| Lane | Branch | Role |
|---|---|---|
| Claude Code | `claude/excel-models-templates-opensource-26937n` | Broad archetype construction, model-specific hardening, independent spreadsheet regression tests |
| ChatGPT/Codex prototype | `agent/integrate-finance-model-library` | Institutional credit/public-finance depth, governance, structural validation, refresh hardening |
| Synthesis | `agent/synthesize-finance-model-library-v2` | Canonical integration lane, based on Claude's latest validated model tree |

## Verified repository baseline

Generated by `tools/validate_model_inventory.py`:

- 24 core archetypes
- 7 M2 Decision Models
- 17 M1 Correct Skeletons
- 0 M3 Institutional Underwriting Models
- 0 M4 Maintained Production Systems
- 0 populated public instances
- no inventory errors
- no maturity-claim validation errors

Formula count and sheet count are recorded as structural evidence, not used as standalone quality scores.

## External-review findings applied

| Finding | Response |
|---|---|
| Core formulas are mostly correct | Preserved existing spreadsheet verification and added dependency-free reference engines |
| Depth is materially below production models | Added explicit M0–M4 maturity scale and conservative baseline |
| Governance is stronger than model content | Made governance executable while defining six flagship depth programs |
| Almost no populated instances | Added a public instance and outcome-monitoring standard |
| Need FAST / ICAEW alignment | Added model design, review, evidence, and handoff controls without claiming certification |
| Need bank-grade model risk | Adopted inventory, conceptual soundness, effective challenge, ongoing monitoring, outcomes analysis, change control, and retirement |
| Need project / DFI depth | Added long-horizon project-finance and blended-finance engine requirements |
| Need pension / endowment / SWF perspective | Defined a cross-domain total-portfolio layer rather than another isolated template |
| Need code reference implementations | Added Python engines now; Zig parity remains a future gate |
| Need elite-firm “insider baseball” | Reframed as public, testable stakeholder perspectives and financial identities rather than unverifiable imitation of proprietary internal models |

## Flagship review and promotion queue

1. Private Equity / Merchant Banking
2. Private Credit / Debt Finance
3. Options / Fixed Income / Rates
4. Project Finance / Infrastructure
5. Structured Finance / Insurance
6. Quantitative / Systematic / Risk

For each flagship, record:

- financial identities added or corrected
- domain-engine completeness
- stakeholder perspectives
- independent benchmark tests
- source and audit improvements
- scenario, sensitivity, and reverse-stress behavior
- builder/workbook parity
- public instance plan
- any regression versus the previous baseline

## Merge blockers

- Synthesis CI and independent-oracle tests must remain green.
- No workbook may contain external links or literal Excel errors.
- The inventory must remain complete and internally consistent.
- No model may be promoted above its evidence.
- Credit and public-finance institutional builders must be reconciled with reviewed release artifacts.
- At least one flagship evidence pack should be completed before calling the governance layer operational in practice.
- The owner must explicitly approve promotion from draft to merge-ready.
